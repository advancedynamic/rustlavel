Guide

From nothing to a running application with a database behind it.

Install the CLI

cargo install rustlavel-cli

This gives you rustlavel, which is the Artisan equivalent: it scaffolds projects, generates controllers and migrations, runs a development server, and diagnoses a misconfigured application.

Scaffold a project

rustlavel new blog --with db,view,auth
cd blog
rustlavel serve

The skeleton is deliberately slim, following Laravel 11 and later: routes, one controller, config, a public directory, tests. Everything else arrives as a package.

--with is the scaffold-time form of cargo add. What you do not ask for is never compiled into your binary, so an application with no mailer does not ship one. That is a real difference rather than a slogan — the benchmark found a comparable Loco application shipping an SMTP client and three cloud storage backends it never used.

Routes

Routes are ordinary Rust, registered on a Router. There is no route file scanned at runtime and no attribute macro reflecting over your handlers.

use rustlavel::prelude::*;

pub fn routes(r: &mut Router) {
    r.get("/", |_req: Request| async move {
        Response::text("Hello, World!")
    });

    r.get("/users/{id}", controllers::users::show).name("users.show");

    r.group("/admin", |admin| {
        admin.middleware(Authenticate::default());
        admin.get("/dashboard", controllers::admin::dashboard);
    });
}

Parameters come out of the request by name, groups carry a prefix and a middleware stack, and a named route can be reversed with url_for.

The database

A connection is application state, so a handler asks for it rather than reaching for a global.

let db = Database::connect("postgres://user:pass@localhost/app?sslmode=verify-full").await?;
App::new()?.state(db).routes(routes).run().await

Set sslmode deliberately. It defaults to prefer, matching libpq — which asks for encryption and accepts a server that declines, so it guarantees nothing against an attacker who can answer "no TLS". Anything crossing a network you do not own wants verify-full. Running rustlavel doctor will say so out loud.

The query builder cannot be injected into: values are bound, identifiers are validated against an allowlist, and an update or delete with no filter is refused rather than quietly emptying a table.

let posts = db.table("posts")
    .where_eq("published", true)
    .order_by("created_at", "desc")
    .limit(20)
    .get()
    .await?;

Models and relations

#[derive(Model)]
#[model(table = "posts")]
struct Post {
    id: i64,
    title: String,
    user_id: i64,
}

The derive is a hand-written proc macro — no syn, no quote — and its errors are written to be read by a person. Relations load without N+1: has_many and belongs_to fetch in one round trip for the whole set.

Migrations and seeders

rustlavel make:migration create_posts_table
rustlavel migrate
rustlavel migrate:rollback
rustlavel db:seed

The migration list is a generated registry rather than a directory scanned at boot. A compiled program cannot discover types by looking at files, and pretending otherwise would mean giving up the compile-time guarantees that are the point.

Templates

@extends("layouts.app")

@section("content")
  <h1>{{ title }}</h1>
  @foreach(posts as post)
    <article>{{ post.title }}</article>
  @endforeach
@endsection

Blade-shaped, with escaping that cannot be switched off by accident, and reload-from-disk while you are developing.

Making stored files public

Uploads belong under storage/app, outside the web root — a directory the server hands out verbatim is not one anybody should be able to write arbitrary files into. But some of those files are meant to be seen.

rustlavel storage:link

That links public/storage to storage/app/public, so one copy of each file is reachable over HTTP and the rest of storage/app stays out of reach. Running it again is not an error, which matters because it belongs in a deploy script.

It refuses to delete a real directory at public/storage, even with --force. That directory may hold files this command did not put there, and removing them is not a risk it gets to take on your behalf. --force repoints a link; it does not delete anybody's files.

What is different from Laravel

LaravelRustlavel
Facades and a runtime containerTyped application state, resolved at compile time
Auto-discovered service providersOne explicit .plugin(...) line
Migrations found by scanning a folderA registry the CLI generates
DB::transaction(fn () => ...)A guard: begin, commit, rolls back when dropped

The transaction difference is not taste. A closure returning a future that borrows its argument cannot express the lifetime it needs, so the guard is what the language actually allows.

Diagnosing a problem

rustlavel doctor

Checks the toolchain, .env, the application key, the port, whether the database is reachable, what the connection is actually encrypted with, the directory layout, and whether the thing compiles.
