Packages

One crate per package. What you do not enable is never compiled.

Everything optional is a feature flag on the rustlavel meta-crate. Add what you need and nothing else reaches your binary:

cargo add rustlavel --features db,view,auth

Or take a single package on its own, the way you would composer require one Illuminate component:

cargo add rustlavel-db

This matters more than it sounds. The benchmark in this repository found a comparable Loco application shipping an SMTP client and three cloud storage backends it never used, because they are unconditional dependencies there. 14 MB against 4 MB, for an application that has neither a mailer nor object storage.

Two packages that are split on purpose

rustlavel-oauth holds the wire vocabulary — scopes, the RFC 6749 error codes, PKCE, the token response — and the client half, the one you use to sign users in through Google or GitHub. rustlavel-oauth-provider depends on it for those types, so both ends of the protocol agree on the format by construction rather than by review.

rustlavel-auth carries its own simpler Scopes type for API tokens. That duplication is deliberate: personal access tokens must not drag an OAuth dependency into the authentication crate.

Databases

PostgreSQL, MySQL and SQL Server, each wire protocol written here, each with TLS. Oracle is deliberately excluded — its network protocol has never been published, so a driver means either wrapping the proprietary OCI library or a multi-year reverse-engineering effort, and neither fits a framework whose premise is that the protocols are written here.
