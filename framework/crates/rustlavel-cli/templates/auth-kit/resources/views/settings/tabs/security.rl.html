Security Policies

@if(s.auth_password_min_length.locked) Set by {{ s.auth_password_min_length.env }} in the environment. @else Length is the rule that actually helps. Longer beats complicated. @endif

@if(s.auth_password_reuse.locked) Set by {{ s.auth_password_reuse.env }} in the environment. @else How many old passwords are remembered and refused. @endif

@if(s.auth_session_timeout.locked) Set by {{ s.auth_session_timeout.env }} in the environment. @else How long an idle session stays signed in. @endif

@if(s.auth_lockout_attempts.locked) Set by {{ s.auth_lockout_attempts.env }} in the environment. @else Wrong passwords before the account locks. “No limit” leaves guessing unbounded, and only the per-address limit standing. @endif

@if(s.auth_lockout_minutes.locked) Set by {{ s.auth_lockout_minutes.env }} in the environment. @else How long a locked account stays locked. The sign-in page tells the person how much of it is left. @endif

Password Complexity

All off by default, and that is deliberate. Composition rules push people towards Password1! and away from the long passphrase that is actually harder to guess, which is why NIST dropped them in SP 800-63B. They are here because organisations are required to have them, not because they help.
